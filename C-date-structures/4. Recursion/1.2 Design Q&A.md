### Q1: What is the base case for factorial?

**You said:** "The smallest number whose factorial I know directly"

**Correct.** That's `1` (since 1! = 1). You could also use `0` (since 0! = 1), but `1` is simpler.

### Q2: What is the recursive case?

**You said:** `n * factorial(n-1)`

**Correct.** This is the exact recurrence.

### Q3: How many calls for `factorial(5)`?

**You said:** `5?`

**Correct.** The calls are:

```
factorial(5)
factorial(4)
factorial(3)
factorial(2)
factorial(1)   ← base case, stops here
```

That's 5 calls.

### Q4: What happens with `factorial(-1)`?

**You said:** "Error because the base case was factorial(1)"

**Correct.** It would call `factorial(-1)`, then `factorial(-2)`, then `factorial(-3)`, forever. It never hits the base case (1), so it runs out of stack memory and crashes (stack overflow).

---

### Q5: Difference between recursion and loop in terms of memory?

**You said:** "Stack - LIFO. Recursion runs last in last out while loop is last in first out"

**Correction:**

| Concept | What happens |
| :--- | :--- |
| **Recursion** | Each call **pushes** a new frame onto the stack. The last call (base case) returns first. This is **LIFO** (Last In, First Out). |
| **Loop (iteration)** | No new stack frames are created. The loop runs sequentially. It does **not** use the call stack for each iteration. |

So recursion **uses the stack**, iteration does **not**.

---

### The Correct Statement

> **Recursion uses the call stack (LIFO). Loops run sequentially and do not grow the stack.**

## Recursion vs Loop (Visual)

**Loop:**
```
factorial(5) with loop:
sum = 1
i = 1 → sum = 1
i = 2 → sum = 2
i = 3 → sum = 6
i = 4 → sum = 24
i = 5 → sum = 120
```
Memory usage: **constant** (just one variable).

**Recursion:**
```
factorial(5)
  → factorial(4)
    → factorial(3)
      → factorial(2)
        → factorial(1)
          → returns 1
        → returns 2
      → returns 6
    → returns 24
  → returns 120
```
Memory usage: **grows** with each call (stack frames).
